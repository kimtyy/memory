### 2. 콘텐츠 기획 및 데이터 수집 단계 (Content Planning & Data Collection)

#### A. 콘텐츠 기획 (Content Planning)

이 단계에서는 **무엇을(What)** 정의할지, 즉 데이터 구조에 포함되어야 할 핵심 요소와 그 관계를 기획합니다.

1.  **MVP 핵심 기능 정의 (What to Measure):**
    *   수익화에 직접적으로 연결되는 핵심 지표(KPIs)를 데이터로 정의한다. (예: 사용자 행동, 구독 상태, 수익 발생 기록)
    *   사용자 경험(UX)에 필수적인 데이터 필드를 식별한다.
2.  **비즈니스 요구사항 정제 (Business Constraint):**
    *   현재까지 논의된 모든 비즈니스 목표(수익화 모델, 타겟 사용자 정의)를 데이터 필드에 대한 **제약 조건**으로 변환한다. (예: "구독자 관리가 핵심이므로, 구독 상태 필드는 필수이다.")
3.  **기술적 제약 조건 정의 (Technical Constraint):**
    *   선택된 기술 스택(DB 종류, API 제한 등)을 고려하여, 데이터 구조가 기술적으로 구현 가능한지 검토하는 기준을 설정한다.

#### B. 데이터 수집 (Data Collection)

이 단계에서는 **어디서(Where)** 정보를 가져올지, 즉 추론이 아닌 사실 기반의 데이터를 수집합니다.

1.  **내부 메모리 및 대화록 분석 (Internal Memory Mining):**
    *   `memory` 파일 및 이전 대화록(`2026-04-29` 등)에서 논의된 **수익화 모델, 핵심 앱 선정 이유, 기존 기능 정의**를 추출하여 데이터베이스로 구성한다.
2.  **경쟁사 데이터 분석 (Competitor Benchmarking):**
    *   경쟁 채널 분석(`competitor_brief`) 및 트렌드 스나이퍼(`trend_sniper`) 결과를 검토하여, 성공적인 MVP가 포함해야 할 **필수 데이터 포인트**를 외부 사례를 통해 보강한다.
3.  **기술적 제약 데이터 확보 (Technical Feasibility Check):**
    *   개발 환경 및 API 제한 사항에 대한 내부 문서를 확인하여, 데이터 필드 설계 시 **실제 구현 가능성**에 대한 제약 데이터를 확보한다.
