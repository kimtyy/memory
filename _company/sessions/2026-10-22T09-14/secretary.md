# 📱 영숙 — 음원 P2P 서비스의 MVP(Minimum Viable Product) 요구사항 정의 및 초기 기술 스택 선정.

## 🎵 음원 P2P 서비스 MVP 요구사항 정의 및 초기 기술 스택 선정 보고서

**[목표]** 음원 P2P 서비스의 최소 기능 제품(MVP)에 필요한 핵심 기능 목록을 정의하고, 각 기능에 대한 현실적인 기술 스택을 제안하여 초기 개발 방향을 설정합니다.

---

### 1. MVP 핵심 기능 목록 (Feature List) 정의

MVP 단계에서는 핵심 가치(음원 공유 및 교환)에 집중하고, 복잡한 부가 기능(광고, 정교한 추천 알고리즘 등)은 추후 단계로 미룹니다.

| ID | 기능 카테고리 | 세부 기능 설명 (MVP Scope) | 목표 (Why) | 우선순위 |
| :--- | :--- | :--- | :--- | :--- |
| **F1** | **사용자 관리** | 회원가입, 로그인 (소셜 로그인 옵션 포함), 프로필 관리 | 서비스 접근 및 개인화의 기반 마련 | **필수 (Must)** |
| **F2** | **음원 업로드** | 사용자가 자신의 음원 파일(MP3, FLAC 등)을 서버에 업로드 | P2P 거래의 대상이 되는 콘텐츠 확보 | **필수 (Must)** |
| **F3** | **음원 검색** | 제목, 아티스트, 앨범 기반의 기본적인 검색 기능 | 사용자가 원하는 음원을 쉽게 찾을 수 있도록 지원 | **필수 (Must)** |
| **F4** | **P2P 공유/거래** | 사용자가 원하는 음원을 다른 사용자에게 요청하거나 직접 공유하는 메커니즘 | 서비스의 핵심 기능 (P2P 교환) | **필수 (Must)** |
| **F5** | **파일 스트리밍** | 공유된 음원을 다운로드하거나 스트리밍하여 감상하는 기능 | 실제 사용자 경험 제공 | **필수 (Must)** |
| **F6** | **기본 피드백** | 공유된 음원에 대한 간단한 '좋아요' 또는 '평점' 기능 | 커뮤니티 기반의 신뢰도 형성 시작 | **권장 (Should)** |
| **F7** | **보안/접근 제어** | 업로드된 파일에 대한 기본적인 접근 권한 관리 | 저작권 및 보안 문제의 초기 방어 | **필수 (Must)** |

---

### 2. 초기 기술 스택 (Technology Stack) 제안

MVP의 목표는 **신속한 프로토타이핑**과 **대용량 파일 처리**에 중점을 두어야 합니다.

#### A. 백엔드 (Backend)

| 영역 | 제안 기술 | 선정 이유 |
| :--- | :--- | :--- |
| **언어/프레임워크** | **Python (Django/FastAPI)** 또는 **Node.js (Express)** | 빠른 개발 속도, 방대한 라이브러리, 대용량 데이터 처리 및 API 개발 용이성. (FastAPI 추천: 고성능 API 구축에 유리) |
| **데이터베이스** | **PostgreSQL** | 관계형 데이터(사용자 정보, 거래 기록)의 무결성 보장 및 확장성. |
| **파일 저장소** | **Amazon S3 (또는 Google Cloud Storage)** | 대용량의 음원 파일(Binary Data)을 안정적이고 확장성 있게 저장 및 관리. |
| **실시간 통신** | **WebSockets (또는 단순 REST API)** | 실시간 채팅이나 상태 업데이트(거래 진행 상황) 처리를 위한 기반. |

#### B. 프론트엔드 (Frontend)

| 영역 | 제안 기술 | 선정 이유 |
| :--- | :--- | :--- |
| **프레임워크** | **React** 또는 **Vue.js** | 컴포넌트 기반으로 복잡한 UI(검색, 파일 업로드 인터페이스)를 효율적으로 구축 가능. |
| **상태 관리** | **Redux/Zustand (React)** 또는 **Vuex (Vue)** | 사용자 세션 및 파일 상태의 복잡한 관리를 체계화. |

#### C. 인프라 및 배포 (Infrastructure & Deployment)

| 영역 | 제안 기술 | 선정 이유 |
| :--- | :--- | :--- |
| **클라우드** | **AWS (Amazon Web Services)** | S3(파일 저장), EC2/Lambda(서버), RDS(DB) 등 필요한 모든 서비스를 통합적으로 제공하는 생태계가 가장 성숙함. |
| **컨테이너화** | **Docker** | 개발 환경과 배포 환경의 일관성 보장, 환경 설정 오류 최소화. |
| **배포** | **AWS ECS/EKS 또는 Vercel/Netlify (Frontend)** | MVP 단계에서는 관리 오버헤드가 적고 확장성이 좋은 PaaS/컨테이너 환경을 우선 고려. |

---

### 3. 다음 단계 제안 (Next Steps)

1.  **기술 검증 (Feasibility Check):** 선정된 스택(FastAPI + PostgreSQL + S3)으로 **F2 (업로드)와 F5 (스트리밍)**의 프로토타입을 우선적으로 구현하여 기술적 실현 가능성을 즉시 검증합니다.
2.  **UX 흐름 구체화:** Designer Agent의 UX 흐름 초안을 바탕으로, **F4 (P2P 공유/거래)** 기능에 대한 구체적인 API 명세와 데이터베이스 스키마 초기 구상을 다음 단계에서 보완할 계획입니다.
3.  **수익화 모델 연계:** MVP 출시 후, F6(피드백)와 연계하여 초기 사용자 참여도를 측정하고, 향후 수익화(예: 구독, 광고) 모델을 연계할 지점을 명확히 설정합니다.
