## 사용자 핵심 기능(업로드, 공유 요청, 피드백) 사용자 흐름(User Flow) 및 초기 UI 요구사항 정의

CEO의 지시사항에 따라, P2P 음원 서비스의 핵심 기능인 '업로드', '공유 요청', '피드백'에 대한 사용자 흐름 초안과 각 단계별 인터페이스(UI) 요구사항을 아래와 같이 정의합니다. 이 흐름은 사용자의 심리적 목표(인지 부하 최소화, 신뢰 구축)를 반영하여 설계되었습니다.

---

### 1. 사용자 흐름 1: 음원 업로드 (Uploader Flow)

**목표:** 사용자가 최소한의 단계로 음원 파일과 메타데이터를 등록하고, 원하는 공유 옵션을 설정하여 업로드를 완료하도록 한다.

| 단계 | 사용자 행동 (Action) | 시스템 반응 (System Response) | UI 요구사항 (Design Requirements) | 핵심 정보 요구사항 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 파일 선택** | '업로드' 버튼 클릭 후 로컬 파일 선택 | 파일 선택 인터페이스 활성화 | 드래그 앤 드롭 지원, 파일 미리보기(썸네일), 파일 형식 제한 명시 | 파일 이름, 파일 크기, 파일 형식 (MP3, FLAC 등) |
| **2. 메타데이터 입력** | 트랙 제목, 아티스트, 장르 등 정보 입력 | 입력 필드 활성화 | 입력 필드 옆에 관련 예시(Placeholder) 제공, 필수는 선택 사항 명시 | 제목, 아티스트, 장르, 분위기 키워드 (태그) |
| **3. 공유 설정** | '공유 옵션' 선택 (공개/비공개/특정 사용자 공유) | 공유 조건 설정 모달(Modal) 표시 | 공유 범위에 대한 명확한 설명, 권한 수준 시각화 (예: 공개 범위 3단계) | 공유 대상 설정 (전체 공개, 친구 공개, 비공개), 공유 기간 설정 |
| **4. 최종 확인** | 모든 정보 검토 후 '업로드 시작' 버튼 클릭 | 업로드 진행 상태 표시 (Progress Bar) | 업로드 진행률 명확히 표시, 업로드 실패 시 명확한 에러 메시지 제공 | 업로드 예상 시간, 오류 코드 (필요시) |

**🎨 디자인 시사점:**
*   **신뢰 구축:** 업로드 과정 중에는 진행률 표시 외에, 데이터 암호화 및 보안 처리 중임을 시각적으로 강조하여 사용자의 신뢰를 확보해야 합니다.
*   **인지 부하 최소화:** 메타데이터 입력 시, AI 기반 자동 태그 제안 기능을 도입하여 사용자가 직접 모든 키워드를 입력하지 않도록 유도해야 합니다.

### 2. 사용자 흐름 2: 공유 요청 (Uploader & Listener Flow)

**목표:** 업로더가 특정 트랙을 리스너에게 공유하고, 리스너가 이를 수신하고 접근하는 과정을 안전하고 명확하게 한다.

| 단계 | 사용자 행동 (Action) | 시스템 반응 (System Response) | UI 요구사항 (Design Requirements) | 핵심 정보 요구사항 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 공유 요청** | 업로더가 특정 트랙을 선택하고 '공유 요청' 실행 | 공유 요청 대기 상태 표시 | 요청 메시지 템플릿 제공 (예: "OOO 님이 [트랙명]을 공유 요청했습니다."), 요청 상태(대기 중/수락됨) 명시 | 공유할 트랙 ID, 공유 요청자 정보 |
| **2. 수신 확인** | 리스너가 알림을 받고 요청 확인 | 알림 피드 또는 알림 센터에 공유 요청 목록 표시 | 알림은 명확하고 즉각적이어야 하며, 누락 방지를 위해 푸시 알림과 인앱 알림을 모두 제공 | 요청된 트랙 정보 (제목, 아티스트), 공유자의 프로필 정보 |
| **3. 접근 및 수락** | 리스너가 공유된 트랙 목록에서 해당 요청을 확인하고 '수락' | 공유 권한 부여 및 스트리밍 연결 시작 | '수락' 버튼은 명확하며, 수락 시 발생할 권한 변화(접근 범위)를 명시해야 함 | 공유된 음원 파일 접근 권한, 스트리밍 방식 (온디맨드/스트리밍) |

**🎨 디자인 시사점:**
*   **투명성:** 공유 요청과 수락 과정은 투명해야 합니다. 특히, **누가, 무엇을, 언제 공유했는지**에 대한 정보는 명확하게 표시되어야 합니다.
*   **상황 인식:** 리스너가 요청을 확인하는 순간, 해당 콘텐츠가 자신의 라이브러리에 어떻게 통합될지(예: 보관함, 플레이리스트)를 시각적으로 제시해야 합니다.

---

### 3. 사용자 흐름 3: 피드백 제공 (Listener Flow)

**목표:** 리스너가 수신한 콘텐츠에 대해 건설적이고 구체적인 피드백을 제공하여 커뮤니티의 질을 향상시킨다.

| 단계 | 사용자 행동 (Action) | 시스템 반응 (System Response) | UI 요구사항 (Design Requirements) | 핵심 정보 요구사항 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 피드백 접근** | 리스너가 콘텐츠 상세 페이지에서 '피드백하기' 버튼 클릭 | 피드백 입력 폼 활성화 | 피드백의 종류(평점/댓글/분석)를 명확히 구분하여 제시 | 피드백 유형 선택 (별점, 코멘트, 기술 피드백) |
| **2. 피드백 입력** | 원하는 평점(1~5점) 및 상세 코멘트 입력 | 입력 내용 저장 및 검증 | 평점과 코멘트 입력란의 명확한 구분, 코멘트 입력 시 최소/최대 글자 수 가이드라인 제공 | 평점 (1-5점), 상세 코멘트 (최소 10자 권장) |
| **3. 피드백 제출** | '제출' 버튼 클릭 | 피드백이 시스템에 기록됨 | 제출 완료 메시지 표시, 피드백이 커뮤니티에 어떻게 반영되는지에 대한 간략한 설명 (선택 사항) | 제출 시간, 피드백 상태 (접수됨) |

**🎨 디자인 시사점:**
*   **정량화와 질적 평가의 균형:** 평점(정량적)과 코멘트(질적) 입력 필드를 명확히 분리하여 사용자가 원하는 방식으로 피드백을 제공하게 해야 합니다.
*   **긍정적 강화:** 피드백을 제공한 사용자에게는 작은 보상(뱃지 등)을 제공하여 참여를 유도하는 디자인 요소를 추가할 것을 제안합니다.
