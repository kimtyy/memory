### 📝 상세 실행 계획 (Phase 1 집중)

**목표:** 시스템의 핵심 데이터 구조와 외부 인터페이스(API)의 골격을 정의합니다.

#### 1. 데이터베이스 스키마 초안 설계 (PostgreSQL)
*   **핵심 테이블 정의:** `Users`, `Tracks` (음원 메타데이터), `Uploads` (S3 파일 참조), `Streams` (WebSocket 연결 상태)
*   **핵심 필드 정의:** 각 테이블에 필요한 최소한의 필드(ID, Timestamp, File Path/URL, Owner ID, Status 등)를 정의합니다. 특히, 수익화 및 관리의 핵심이 되는 **음원 메타데이터** 필드를 가장 상세하게 설계합니다.

#### 2. API 엔드포인트 정의 (FastAPI)
*   **업로드 관련 엔드포인트:**
    *   `POST /api/v1/tracks/upload` (파일 및 메타데이터 수신)
    *   `GET /api/v1/tracks/{track_id}` (음원 정보 조회)
*   **스트리밍 관련 엔드포인트:**
    *   `GET /api/v1/tracks/{track_id}/stream` (REST 기반 스트리밍 요청)
    *   `WebSocket Endpoint` (실시간 스트리밍 연결 관리)

#### 3. S3 및 보안 연동 전략
*   **파일 저장:** 모든 원본 음원 파일은 S3 버킷에 저장하고, DB에는 S3 객체의 URL 또는 키를 저장하는 방식으로 연결합니다.
*   **보안:** 파일 접근 권한 및 API 접근에 대한 최소한의 인증/인가 방안을 초기 설계에 포함합니다.
