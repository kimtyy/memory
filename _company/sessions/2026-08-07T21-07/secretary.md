# 📱 영숙 — P2P 음악 서비스 및 판매 앱의 핵심 사용자 스토리(User Stories) 및 필수 기능 목록을 정의하고, 이를 기반으로 초기 기술 스택(프론트엔드/백엔드)에 대한 제안을 준비하라.

## 🚀 P2P 음악 서비스 및 판매 앱: 핵심 기능 정의 및 초기 기술 스택 제안

CEO님의 지시에 따라, P2P 음악 서비스 및 판매 앱의 성공적인 출시를 위한 핵심 사용자 스토리(User Stories)와 필수 기능 목록을 정의하고, 이를 기반으로 초기 기술 스택(프론트엔드/백엔드)에 대한 현실적인 제안을 준비했습니다.

---

### 1. 핵심 사용자 스토리 (User Stories) 정의

이 서비스의 목표는 사용자들이 자신의 음악을 안전하게 거래하고 수익을 창출할 수 있도록 하는 것입니다.

| ID | 사용자 역할 (As a...) | 목표 (I want to...) | 결과 (So that...) | 우선순위 |
| :--- | :--- | :--- | :--- | :--- |
| **US1** | 음악 판매자 (Seller) | 내 음악 파일을 쉽게 업로드하고 상세 정보를 등록하고 싶다. | 내 음악을 안전하게 시장에 제시하고 수익을 얻고 싶다. | **필수 (P1)** |
| **US2** | 구매자 (Buyer) | 원하는 음악을 검색하고 상세 정보를 보고 싶다. | 원하는 음악을 안전하고 편리하게 구매하고 싶다. | **필수 (P1)** |
| **US3** | 모든 사용자 | 안전한 개인 프로필과 거래 기록을 관리하고 싶다. | 신뢰를 바탕으로 지속적인 거래를 할 수 있고, 자신의 활동을 추적하고 싶다. | **필수 (P1)** |
| **US4** | 판매자/구매자 | 명확하고 안전한 결제 시스템을 통해 거래를 완료하고 싶다. | 복잡한 외부 연동 없이 앱 내에서 안전하게 돈을 주고받고 싶다. | **핵심 (P2)** |
| **US5** | 모든 사용자 | 음악 콘텐츠의 저작권 및 무단 공유 문제를 최소화하고 싶다. | 법적/기술적 리스크를 줄이고 플랫폼에 대한 신뢰도를 높이고 싶다. | **중요 (P3)** |

### 2. 필수 기능 목록 (MVP Scope)

위 사용자 스토리를 충족시키기 위해 MVP 단계에서 반드시 구현해야 할 핵심 기능 목록은 다음과 같습니다.

#### A. 사용자 및 인증 관리 (Authentication & Profile)
1.  **회원가입/로그인:** 소셜 로그인(선택 사항) 및 이메일 기반 인증.
2.  **사용자 프로필 관리:** 닉네임, 연락처, 판매/구매 통계 등 상세 정보 관리.
3.  **보안 설정:** 비밀번호 변경 및 2단계 인증 지원.

#### B. 음악 콘텐츠 업로드 및 관리 (Content Management)
1.  **음악 파일 업로드:** 고화질 오디오/비디오 파일 업로드 기능 (파일 크기 제한 포함).
2.  **상세 정보 입력:** 트랙 제목, 아티스트, 장르, 앨범 정보, 가격, 상태(판매/대여) 명시.
3.  **업로드 관리:** 판매 중인 목록과 내 음악 라이브러리 관리 기능.

#### C. 검색 및 탐색 (Search & Discovery)
1.  **통합 검색:** 제목, 아티스트, 장르별로 음악을 검색하는 강력한 기능.
2.  **필터링:** 가격대, 상태(새 상품/중고), 인기순 등으로 필터링 기능 제공.

#### D. 거래 및 결제 시스템 (Transaction & Payment)
1.  **구매 요청:** 구매자가 판매자에게 직접 구매를 요청하는 기능.
2.  **안전한 결제 연동:** 앱 내에서 안전하게 금액을 지불하고 대금을 확보하는 시스템 (초기에는 외부 PG사 연동 검토).
3.  **거래 기록:** 모든 거래 내역(판매, 구매 성공/실패)의 투명한 기록 관리.

### 3. 초기 기술 스택 제안 및 분석

MVP의 요구사항(대용량 파일 처리, 실시간 검색, 보안성)을 고려하여 **확장성과 개발 속도**를 동시에 확보할 수 있는 스택을 제안합니다.

#### 🎯 제안 아키텍처: MERN/PERN 기반의 분산 시스템

| 영역 | 추천 기술 스택 | 선택 이유 및 분석 (난이도) |
| :--- | :--- | :--- |
| **프론트엔드 (Frontend)** | **React (Next.js 권장)** | 시장 선호도가 높고, 대규모 SPA(Single Page Application) 구축에 용이함. Next.js를 사용하여 초기 SEO 및 서버리스 기능 통합을 통해 개발 속도 향상. (난이도: 중) |
| **백엔드 (Backend)** | **Node.js (Express/NestJS)** | 비동기 처리 능력이 뛰어나 대용량 파일 I/O(음악 파일) 처리에 유리하며, 프론트엔드와 동일 언어 사용으로 개발 효율성 증대. (난이도: 중상) |
| **데이터베이스 (Database)** | **PostgreSQL** | 트랜잭션 무결성이 매우 중요하므로 관계형 데이터베이스의 강점을 활용. 사용자, 거래 기록 등 정형화된 데이터 관리에 최적. (난이도: 중) |
| **파일 저장소 (Storage)** | **AWS S3 또는 Google Cloud Storage** | 음악 파일과 같은 대용량 미디어 파일을 안전하고 확장성 있게 저장하기 위해 클라우드 객체 스토리지를 사용. (난이도: 하) |

#### 📊 기술적 실현 가능성 및 난이도 평가

| 항목 | 평가 | 상세 분석 |
| :--- | :--- | :--- |
| **기술 스택 선택** | **높음** | MERN/PERN 기반은 현재 시장에서 가장 빠르게 개발팀을 구성하고 인력을 확보할 수 있는 표준적인 조합입니다. |
| **데이터 보안 (US5)** | **중상** | 파일 업로드 시 암호화(Encryption at Rest/In Transit) 및 접근 권한 관리가 핵심 난이도 요소입니다. PG 연동 시에는 PCI DSS 준수 수준을 고려해야 합니다. |
| **파일 처리 (US1)** | **중** | S3에 파일을 저장하고 DB에 파일 경로만 저장하는 구조가 가장 효율적입니다. 대용량 파일 업로드 시 발생하는 시간 초과 및 오류 처리가 기술적 난이도를 결정합니다. |
| **결제 연동 (US4)** | **상** | 외부 결제 API(PG) 연동은 보안 규정 준수와 에러 핸들링 측면에서 높은 설계 난이도를 요구합니다. MVP 단계에서는 간소화된 방식으로 시작해야 합니다. |

### 💡 최종 권고 사항

1.  **MVP 집중:** 초기에는 **US1, US2, US3**에 완벽하게 집중하고, 결제 시스템(US4)은 **PoC(Proof of Concept)** 수준으로 구현하여 시장 반응을 확인한 후 확장하는 것을 권장합니다.
2.  **인프라 우선 구축:** 백엔드와 데이터베이스의 스키마를 먼저 설계하고, 파일 저장소(S3) 연동 테스트부터 진행해야 실질적인 개발 난이도를 예측할 수 있습니다.
3.  **개발 순서 제안 (3개월 로드맵 기반):**
    *   **1개월 차:** 기본 인증/프로필 기능 및 S3 파일 업로드/다운로드 API 구현.
    *   **2개월 차:** 핵심 검색 기능(DB 쿼리 최적화) 및 판매 목록 표시 화면 개발.
    *   **3개월 차:** 구매 요청 로직 및 최소한의 결제 연동 흐름(테스트 환경) 구축.
